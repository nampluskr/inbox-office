# MULTI-AGENT — 문서 기반 작업 배분

## 가용 에이전트 확인

구성 범위는 현재 사용하는 도구 안의 에이전트다. 다른 도구와의 연결을 전제하지 않는다.
멀티에이전트 계획을 세우기 전에 사용자에게 다음을 묻고 답변을 받는다.

> 현재 도구에서 사용할 수 있는 에이전트 목록과 각 에이전트의 역할·제약을 알려 주세요.
> 하나만 사용할 수 있으면 단일 에이전트로 구성하겠습니다.

이미 이번 작업에 대한 답변을 받았다면 그 답변을 사용하고 반복해서 묻지 않는다.
목록을 임의로 가정하거나 예전 버전의 목록이 여전히 유효하다고 간주하지 않는다.
답변을 기다리는 동안 에이전트 배분과 무관한 문서 정리는 진행할 수 있다.

사용자 답변과 현재 도구가 제공하는 실제 기능·권한을 대조한다.
사용할 수 없는 항목은 사용자에게 알리고 실제 실행 가능한 구성으로 조정한다.
에이전트가 하나이거나 나눌 작업이 없으면 단일 구성으로 진행한다.

## PLAN에 기록할 내용

| 항목 | 내용 |
| --- | --- |
| 가용 목록 | 사용자 답변과 현재 도구에서 확인한 제약 |
| 담당 작업 | 작업 번호와 대응 SPEC 요구 |
| 역할 | 구현, 조사, 검토 등 이번 작업의 책임 |
| 수정 범위 | 담당 파일 또는 영역과 다른 작업과의 경계 |
| 의존 관계 | 먼저 끝나야 하는 작업과 병렬 수행 가능 여부 |
| 통합 담당 | 결과를 합치고 최종 검증할 담당 |

## 실행과 통합

1. 각 담당자에게 프로젝트 INTENT, 해당 버전 문서 경로, 맡은 작업과 완료 기준을 전달한다.
2. 독립적인 작업만 병렬 수행한다. 같은 파일을 수정해야 하면 순서를 정하거나 통합 담당자가 반영한다.
3. 담당자는 변경 내용, 검증 결과, 미해결 사항을 통합 담당자에게 전달한다.
4. 계획 변경은 통합 담당자가 PLAN에 반영하고, 진행·요청 작업 기록은 PROGRESS에 모아 기록 충돌을 줄인다.
5. 통합 담당자는 SPEC 기준으로 전체 결과를 확인하고 해당 Phase의 결과를 PROGRESS에 기록한다.

작업을 나눴다는 이유로 요구나 설계 결정을 에이전트가 추가하지 않는다.
실제 에이전트 실행에는 현재 도구의 권한과 상위 지침이 적용된다.
