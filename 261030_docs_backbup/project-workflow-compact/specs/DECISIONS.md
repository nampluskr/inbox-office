# DECISIONS

## INTENT

- 목적: 사용자가 선택한 구조와 운영 방식을 공통 기준으로 고정한다.
- 범위: 단계, 저장 경로, 템플릿, 에이전트 확인, 참조 전환.
- 기대 결과: SPEC과 PLAN 작성 시 같은 선택을 반복하지 않는다.

## 결정 사항

| 번호 | 대상 | 선택 | 근거 | 검토한 대안 |
| --- | --- | --- | --- | --- |
| D-1 | 프로젝트명 | project-workflow-compact | 사용자 선택 | lite·simple 등 후보에서 compact 선택 |
| D-2 | 단계 | INTENT → DECISIONS → SPEC → PLAN | 절차 축소 | 기존의 복잡한 흐름 유지 |
| D-3 | 저장 | specs/{version}/의 설계 문서 네 개와 PROGRESS | 버전별 설계와 실행 기록을 한곳에서 관리 | current/history 복사 구조 |
| D-4 | 템플릿·단계 의도 | 평면 설계 문서 네 개, 문서 내 INTENT 항목 | 사용자 선택. 실행 기록은 D-9에 따라 추가 | 단계 폴더와 별도 INTENT 파일 |
| D-5 | 에이전트 | 현재 도구 안에서 사용자에게 가용 목록 질문 후 배분 | 사용자 답변 반영 | 여러 도구 연결, 목록 임의 가정 |
| D-6 | 최초 버전 | v0.1 | 사용자 선택 | v1.0 |
| D-7 | 운영 문서 | 공통 절차와 작성·에이전트 지침으로 분리 | 최초에는 진행도 PLAN에 기록했으나 사용자 후속 요청으로 D-9 적용 | 초기화·버전 지침을 각각 필수 문서로 분리 |
| D-8 | 참조 전환 | 문서 검증 후 루트 AGENTS와 목록 갱신 | 승인된 작성 계획 | 기존 프로젝트 일괄 수정 |
| D-9 | 진행 기록 | 버전별 PROGRESS.md와 평면 템플릿 추가 | 사용자가 PLAN의 Phase별 진행사항과 사용자 요청 작업 내역의 별도 기록을 요청 | PLAN 안에 실제 수행 내역 유지 |

## 미결 사항

없음. 이후 요구가 추가되면 사용자 판단에 따라 갱신한다.
