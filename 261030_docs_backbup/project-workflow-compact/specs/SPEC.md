# SPEC

## INTENT

- 목적: 새 워크플로우의 문서와 적용 결과를 검증 가능하게 정의한다.
- 범위: 저장소 구성, 문서 의미, 실행 지침과 루트 참조.
- 기대 결과: 아래 요구별로 완료 여부를 판정할 수 있다.

## 요구사항

| ID | 요구 | 완료 판정 방법 |
| --- | --- | --- |
| R-1 | 네 단계와 버전별 저장 구조를 정의한다 | WORKFLOW와 실제 specs/v0.1의 네 문서 대조 |
| R-2 | 템플릿은 평면 구조의 설계 문서 네 개와 PROGRESS이며, 설계 문서는 각각 INTENT 항목을 갖는다 | 파일 개수·이름·하위 폴더·설계 문서 첫 항목 검사 |
| R-3 | 프로젝트 전체·버전·단계 의도의 관계와 작성 주체를 정의한다 | DOCUMENTS 검토 |
| R-4 | 가용 에이전트는 현재 도구 범위에서 사용자 답변 후 구성한다 | MULTI-AGENT와 PLAN 양식, 단일·복수 사례 검토 |
| R-5 | 신규 시작, 변경, 검증, 버전 종료·다음 버전을 정의한다 | WORKFLOW를 두 시작 사례에 대입 |
| R-6 | 별도 하네스 없이 PLAN으로 Phase별 작업을 정의하고 PROGRESS에 실제 진행·검증을 기록한다 | 필수 설치 요구가 없고 PLAN·PROGRESS의 역할이 구분되는지 검토 |
| R-7 | 루트 기본 참조를 새 가이드로 전환하고 목록을 갱신한다 | 루트 AGENTS 경로·표 및 README 목록 검사 |
| R-8 | 문서 링크와 UTF-8 한글이 유효하다 | 링크 대상 존재, 엄격한 UTF-8 재읽기와 텍스트 점검 |
| R-9 | 사용자 요청 작업의 요청·조치·결과·검증·상태를 PROGRESS에 기록한다 | 가이드·템플릿·이번 요청의 실제 기록 대조 |

## 제약

- 기존 `_clones/project-workflow`와 개별 프로젝트는 수정하지 않는다.
- 폴더 이동, 저장소 초기화, 커밋·배포는 이번 작업에 포함하지 않는다.
- 사용자의 종료 판단 없이 버전을 종료했다고 기록하지 않는다.
