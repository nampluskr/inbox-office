# 결정과 미결 사항

## INTENT

사용자가 확정한 제품 방향과 main에 위임한 MVP 정책 판단을 기록한다. main의 선택은 구현 기준이며 실제 호환성·동작 검증 결과와 구분한다. 선택을 변경할 때는 근거와 영향을 기록하고 Sol에게 전달한다.

## 적용 제약

확정된 요구를 충족하기 어려운 기술 제약이 발견되면 요구를 임의로 축소하지 않고 main에 증거와 대안을 보고한다. 설치 패키지·코드 서명은 이번 MVP의 완료 조건이 아니며 개발 실행과 재현 가능한 빌드를 우선한다. 시간·자원 측정은 조건과 실제 값을 기록하고 임의의 성능 우위를 주장하지 않는다.

## 기술 판단의 확인 자료

2026-10-30 main이 현재 환경에서 Windows 빌드 22631, rustc/cargo 1.99.1을 확인했다. [Kit manifest](https://github.com/longbridge/gpui-kit/blob/main/crates/kit/Cargo.toml)의 0.8.1·syntect 옵션과 [공식 Markdown 예제](https://github.com/longbridge/gpui-kit/blob/main/examples/markdown/src/main.rs)의 편집·텍스트 렌더링·수식 연결을 검토했다. 수식 예제는 Node.js로 MathJax를 실행하므로 기본 Kit 의존성만으로 수식까지 자동 충족된다고 가정하지 않는다. 이는 기술 선택 근거이며 현재 앱에서 빌드·실행을 검증했다는 뜻은 아니다.

## 첫 빌드 보고와 main의 적용 판단

2026-10-30 Sol이 Kit 0.8.1 취득·Cargo.lock 생성 및 GPUI snapshot 0.3.10 고정을 보고했다. 기본 `cargo build --locked --offline`이 2분 33초에 성공하고 네이티브 앱 PID 23636을 시작했다는 보고다. main은 기술 선택 U-9를 유지하고 P-7~P-15 통합을 계속하도록 판단했다. 정확한 실행 명령·측정 조건·로그와 후속 기능 검증 결과는 Sol이 PROGRESS에 기록한다. 이 시간은 보고된 첫 기본 창 빌드의 값이며 전체 MVP 작성 시간이나 R-1~R-14 기능 통과를 뜻하지 않는다.

## 네이티브 캡처·입력 판단 근거

2026-10-30 main이 `scripts/native_smoke.py`와 초기 UI 이미지를 읽었다. 스크립트는 기본 모니터 캡처 후 화면 좌표로 crop하며, main 실행 문맥에서 가상 화면은 `(-2688, 0, 4608, 1080)`으로 조회됐다. 음수 좌표 모니터가 있으므로 `ImageGrab.grab(bbox=window_rect, all_screens=True)` 또는 가상 화면 원점 보정이 필요하다. 저장된 HWND는 main 조회 시 유효하지 않았으나 재시작·데스크톱 문맥 차이가 있을 수 있어 과거 검정 캡처의 원인으로 확정하지 않는다.

- [Pillow ImageGrab](https://pillow.readthedocs.io/en/stable/reference/ImageGrab.html): 모든 모니터 캡처와 HWND 단위 캡처를 제공. 설치된 Pillow 12.3.0에서 두 방식을 비교할 수 있다.
- [Microsoft SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput): 삽입한 이벤트 수를 확인하며 무결성 수준 제약을 고려. 대상 PID가 전경인지 입력 전후 확인하고 기존 Preview 단축키로 상태 전환을 검증한다.
- [Microsoft ClientToScreen](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-clienttoscreen): 좌표 입력이 필요하면 클라이언트 좌표를 화면 좌표로 변환한다.
- [Microsoft UI Automation](https://learn.microsoft.com/en-us/windows/apps/dev-tools/winapp-cli/ui-automation): 실제 입력은 잠금 해제된 대화형 데스크톱이 필요하며 GPU 창 캡처에는 WGC 경로가 있다. 이 프로젝트 환경에는 winapp CLI가 확인되지 않았으므로 미설치 도구를 사용 가능한 방법으로 보고하지 않는다.

main 지시: p4의 동일 문맥에서 HWND·프로세스·데스크톱·최소화·화면 범위·전경 조건을 검사하고, 단축키 입력 후 세션의 실제 Preview 모드를 확인한다. 블랙 프레임은 실패 증거로 보존하고 정상 캡처와 구분한다. 캡처 경로만 막히면 모델·Kit 이벤트 테스트와 실제 화면 검증의 결과를 나눠 보고하며 GUI 항목은 미검증으로 유지한다. 대규모 자동화 도구 설치보다 기존 하네스 보정과 제품 안전성 검증을 우선한다.

Sol 보고에 따르면 p4의 Python 하네스를 `--keep-open`으로 유지하면서 루트 앱 수명을 보존하고 API 반환값·가상 화면 보정을 적용해 상태 전환을 확인했다. main은 p4나 테스트 앱의 실행 상태를 변경하지 않고 저장·충돌·dirty 종료·복원·helper 실패 검증을 계속하도록 지시한다. 캡처의 하단 토글 두 개는 아이콘이 명확히 보이지 않아 최종 빌드에서 Sidebar/Leftbar 아이콘의 가시성과 개별 동작을 확인하도록 남긴다.
