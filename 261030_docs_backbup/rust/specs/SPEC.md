# Markdown Editor 요구사항

## INTENT

Windows Markdown Editor의 화면·편집·Preview·상태 유지 요구를 판정 가능한 단위로 정의한다. 각 R-ID는 이 버전에서 고유하다. 아래 판정은 향후 앱 구현 후 수행할 기준이며 현재 통과 결과가 아니다.

## 요구사항

| ID | 요구 | 완료 판정 기준 | 적용 정책·착수 기준 |
| --- | --- | --- | --- |
| R-1 | Windows에서 Rust + GPUI + GPUI Kit 기반 앱 제공 | 합의된 Windows 환경에서 해당 조합으로 만든 앱을 시작해 기본 창과 한글 표시·입력을 확인한다 | U-9의 버전 조합·호환성 검증 계획, 대상 Windows 환경 확정 |
| R-2 | 왼쪽 Sidebar에서 폴더 추가·선택·등록 해제 | 서로 다른 두 폴더를 등록하고 활성 폴더를 전환한다. 하나를 등록 해제해 목록에서 사라지고 디스크 폴더·파일은 그대로 남는지 확인한다 | U-8의 미저장 상태를 가진 폴더 해제 정책 확정 |
| R-3 | Sidebar 옆 Leftbar에 활성 폴더의 트리 표시 | 활성 폴더의 중첩 폴더를 펼쳐 파일을 선택하면 해당 파일이 오른쪽 원문 탭으로 열린다. 폴더 전환 후 트리가 선택 폴더와 일치한다 | 파일 오류는 U-6·U-7에 따라 확정 후 반영 |
| R-4 | 코드와 Markdown 원문을 구문 강조하고 바로 편집 | 확정한 언어별 샘플과 Markdown을 열어 일반 텍스트와 구문 강조가 구분되고 별도 편집 모드 없이 한글·코드·Markdown을 수정할 수 있다 | U-1·U-2·U-9의 언어·인코딩·편집 구성 확정 |
| R-5 | 편집 내용을 저장 | 지원 인코딩·줄바꿈 샘플을 수정·저장하고 다시 열어 기대 내용과 파일 내용을 대조한다. 저장 성공 뒤 변경 상태가 해제된다 | U-2·U-6의 저장 형식과 충돌 정책 확정 |
| R-6 | Markdown Preview를 별도 탭 또는 오른쪽 분할로 사용하며 미저장 버퍼 반영 | 같은 원문으로 별도 Preview 탭과 오른쪽 분할 표시 방식을 각각 확인한다. 저장 없이 수정한 본문이 확정된 갱신 조건 안에 연결된 Preview에 반영되고 다른 원문과 혼동되지 않는다 | U-3의 연결·배치 전환·중복·갱신 조건 확정 |
| R-7 | Preview에 기본 문법·표·작업 목록·코드 강조·상대 로컬 이미지/링크·인라인/블록 수식 지원 | 확정된 샘플의 제목·문단·목록·강조·인용·코드·링크 등 기본 문법, 표, 완료/미완료 작업 항목, 언어별 코드 강조, 상대 이미지 표시·로컬 링크 동작, 두 형식 수식을 기대 결과와 대조한다 | U-1·U-4·U-5·U-9의 문법·리소스·렌더링 조합 및 샘플 확정 |
| R-8 | 폴더별 탭과 선택 상태 유지 | 폴더 A와 B에서 다른 파일 탭과 선택 상태를 만든 뒤 A→B→A로 전환해 각 폴더의 탭과 확정한 선택 상태가 돌아오는지 확인한다. 전환 전 미저장 변경도 확정 정책에 맞게 유지한다 | U-3·U-7·U-8의 선택 범위·Preview·문서 수명 확정 |
| R-9 | 하단 상태표시줄에 Sidebar·Leftbar 각각 독립 보기/감추기 아이콘, 패널 크기 조절과 상태 복원 | 두 아이콘을 각각 조작해 다른 패널 상태가 바뀌지 않는지 확인한다. 두 패널과 오른쪽 분할의 크기를 조절하고 숨김 후 재표시 및 정상 재시작 시 표시·크기 상태가 복원되는지 확인한다 | U-7·U-10의 저장 범위·크기 보정 기준 확정 |
| R-10 | 재시작 시 등록 폴더 목록과 저장 파일 탭 복원 | 두 폴더에 실제 경로가 있는 파일 탭을 열고 저장한 뒤 정상 종료·재시작하여 등록 목록과 각 폴더의 파일 탭이 복원되는지 확인한다 | U-7의 저장 형식·오류·선택 복원 범위 확정. 미저장 버퍼의 비정상 종료 복구는 확정 요구가 아님 |
| R-11 | 미저장 변경이 있는 정상 종료에 저장/버리기/취소 제공 | 각 선택을 독립 시나리오로 실행한다. 저장은 디스크 반영 후 종료, 버리기는 미저장 내용을 반영하지 않고 종료, 취소는 앱과 편집 내용을 유지한다. 다중 문서·저장 실패도 확정 정책과 대조한다 | U-8의 다중 문서·실패 처리 확정 |
| R-12 | 파일 접근·저장·외부 변경·복원 오류의 처리 기준 마련 및 적용 | 파일 없음·접근 거부·저장 실패·외부 변경 충돌·복원 경로 누락과 손상 상태 데이터를 재현해 확정된 안내·버퍼 보존·재시도 또는 건너뛰기 동작과 대조한다 | main 확정 U-2·U-5·U-6·U-7·U-8의 실패·버퍼 보존 정책 적용 |
| R-13 | 상단 메뉴에 실제 구현한 기능만 노출 | 메뉴 항목별 실제 동작을 실행해 대응 구현을 확인한다. 제외 기능과 동작 없는 미래 기능 항목이 노출되지 않는지 점검한다 | 구현 범위에 맞춰 메뉴 목록 정리. 미정 기능을 확정 메뉴로 추가하지 않음 |
| R-14 | 최종 이미지의 영역 배치와 제품 제외 범위 준수 | [참고 이미지](../../docs/references/zed-layout.png)와 Sidebar·Leftbar·오른쪽 탭/분할·하단 상태표시줄 배치를 대조한다. 터미널, AI/스레드/로그인, 빌드/실행/디버깅, PDF/CSV/이미지 편집, 독립 모듈 앱/확장 설치가 제품 범위에 없는지 확인한다 | 참조 이미지 복사 완료, 앱 통합 시 시각 대조. 픽셀 단위 일치나 이미지 속 모든 기능의 재현을 요구하지 않음 |

## 제약과 검증 기록

최신 요청으로 MVP 구현·설치·빌드·실행·검증을 수행한다. GPUI Kit 기본 구성과 공식 예제를 우선 재사용하며 라이브러리 제공 기능을 제품의 구현 완료로 간주하지 않는다.

위 표의 적용 정책·착수 기준은 main이 [DECISIONS](DECISIONS.md)의 U-1~U-10으로 확정했다. 기존 표의 '확정'·'미정' 표현은 정책 식별과 과거 착수 조건이며 현재 승인 대기가 아니다. UTF-8/BOM과 줄바꿈 보존, 150ms Preview, 저장 전 충돌 확인, JSON 세션 및 문서별 종료 선택을 해당 결정대로 적용한다. PLAN은 위 R-ID를 참조하고 실제 검증은 [PROGRESS](PROGRESS.md)에 환경·입력·관찰 결과를 기록한다. 문서 정합성 검사와 앱 기능 검증은 구분한다.
