# docs/tools 작성 지침

## 적용 범위
- 이 파일은 `docs/tools` 아래의 도구별 CLI 매뉴얼 문서에 적용한다.
- 저장소 전체 규칙은 루트 `AGENTS.md`를 따른다.
- `docs` 전체 공통 규칙은 `docs/AGENTS.md`를 따른다.

## 문서 성격
- `docs/tools` 문서는 사용자가 실제 작업 중 수시로 열어보는 가이드 매뉴얼이다.
- 긴 방법론 설명보다 명령어, 절차, 정상 출력, 확인 방법, 문제 해결을 우선한다.
- AI Agent 사용 철학과 방법론은 길게 설명하지 않고, 도구 사용에 필요한 판단 기준만 짧게 적는다.

## 대상 독자
- VS Code Extension 또는 앱 대화창 사용 경험은 있으나 CLI 사용은 익숙하지 않은 사용자
- Windows PowerShell에서 Codex CLI 또는 Claude Code CLI를 실행하려는 사용자
- Python 수치해석, 딥러닝, C++ 알고리즘 작업에 AI Agent CLI를 활용하려는 사용자

## 문서 템플릿
- 도구별 매뉴얼 문서는 특별한 이유가 없으면 `docs/tools/TEMPLATE.md`를 기준으로 작성한다.
- 문서 앞부분에는 반드시 `언제 보는 문서인가`와 `빠른 결론`을 둔다.
- 명령어는 가능한 한 복사해서 바로 실행할 수 있도록 코드 블록으로 작성한다.
- 정상 출력 예시와 확인 명령을 함께 제공한다.
- 문제 해결 항목은 `증상`, `원인`, `해결 방법` 표를 우선 사용한다.

## 폴더와 파일명 규칙
- Codex CLI 문서는 `docs/tools/codex` 아래에 둔다.
- Claude Code CLI 문서는 `docs/tools/claude` 아래에 둔다.
- 파일명은 `{tool}-{NN}-{topic}.md` 형식을 사용한다.
- 예: `codex-01-setup.md`, `claude-01-setup.md`
- 번호는 사용자가 처음부터 읽을 때의 권장 순서를 나타낸다.

## 도구별 README 동기화 규칙
- `docs/tools`의 전체 구조나 도구 목록이 바뀌면 `docs/tools/README.md`도 함께 확인한다.
- `docs/tools/codex` 아래 문서 목록이 바뀌면 `docs/tools/codex/README.md`를 업데이트한다.
- `docs/tools/claude` 아래 문서 목록이 바뀌면 `docs/tools/claude/README.md`를 업데이트한다.
- 새 문서를 추가할 때는 해당 도구 README에 링크 또는 작성 예정 항목을 반영할지 검토한다.

## 작성 원칙
- 설명보다 실행 가능한 절차를 우선한다.
- 한 문서는 하나의 사용 상황이나 작업 흐름에 집중한다.
- Windows PowerShell 예시를 우선 제공한다.
- macOS, Linux, WSL 차이가 있으면 별도 소제목으로 구분한다.
- 위험 명령, 권한 상승, 파일 삭제, 전체 접근 모드는 주의사항을 먼저 적는다.
- 도구 버전에 따라 달라질 수 있는 기능은 버전 확인 방법을 함께 적는다.
- 문서 끝에는 체크리스트와 관련 문서를 둔다.

## 품질 확인
- 문서 저장 후 UTF-8 인코딩과 한글 깨짐 여부를 확인한다.
- 명령어 코드 블록의 shell 종류를 명시한다.
- 경로와 파일명이 실제 저장 구조와 맞는지 확인한다.
- 정상 출력 예시와 문제 해결 절차가 초보자에게 충분히 구체적인지 확인한다.
