# docs/guides 작성 지침

## 적용 범위
- 이 파일은 `docs/guides` 아래의 AI Agent 작업 방식 가이드 문서에 적용한다.
- 저장소 전체 규칙은 루트 `AGENTS.md`를 따른다.
- `docs` 전체 공통 규칙은 `docs/AGENTS.md`를 따른다.

## 대상 독자
- VS Code Extension 기반 AI Agent 사용 경험은 있으나 CLI Agent 작업 방식은 익숙하지 않은 사용자
- Python 수치해석, 딥러닝, C++ 알고리즘, 코딩테스트 개발 경험이 있는 사용자
- AI Agent와 함께 일하는 방법을 문서화하고 반복 가능한 워크플로우로 만들려는 사용자

## 작성 원칙
- 특정 도구 명령어보다 여러 AI Agent에 공통으로 적용되는 작업 방식과 판단 기준을 우선 설명한다.
- 개념 설명 뒤에는 반드시 실제 작업 장면, 좋은 요청 예시, 흔한 실패 패턴을 연결한다.
- Codex, Claude Code 같은 도구별 명령과 화면 설명은 `docs/tools` 아래 문서로 분리하고, `docs/guides`에서는 링크로 연결한다.
- 초보자가 따라 할 수 있도록 용어를 먼저 정의하고, 이후 점진적으로 고급 개념을 소개한다.
- Python 실험, 딥러닝 실험, C++ 알고리즘 풀이처럼 사용자의 기존 개발 맥락에 맞는 예시를 우선 사용한다.
- 문서의 결론은 `요약`과 `추가 학습할 내용`으로 마무리하고, 필요한 경우 본론 안에 체크리스트를 둔다.

## 문서 기본 구성
각 가이드 문서는 특별한 이유가 없으면 `docs/guides/TEMPLATE.md`를 기준으로 작성한다.

기본 흐름은 다음과 같다.

1. `# {가이드 제목}`
2. `## 초록`
3. `## 서론`
4. 주제별 본론 섹션
5. `## 결론`
6. `## 참고 자료`

`## 초록`은 문서의 주제, 문제의식, 핵심 주장, 독자가 얻을 수 있는 내용을 5~10문장으로 요약한다.

`## 서론`에는 `### 배경`, `### 문제 제기`, `### 목표`를 둔다. `문서의 목표`라는 제목 대신 `목표`를 사용한다.

본론은 `## 본론`이라는 고정 섹션을 만들지 않는다. 문서 내용에 맞는 핵심 주제별 `##` 섹션으로 구성하며, 섹션 개수와 제목은 문서마다 변경하거나 추가할 수 있다.

`## 결론`에는 `### 요약`과 `### 추가 학습할 내용`을 둔다.

`## 참고 자료`에는 공식 문서, 외부 참고 자료, 내부 `docs/refs` 문서 링크를 정리한다.

## 상위 분류별 작성 초점
| 분류 | 작성 초점 |
|---|---|
| AI Agent 작업 모델 | 챗봇형 대화와 Agent형 작업의 차이, 파일 수정과 명령 실행을 포함한 작업 방식 |
| 지침과 작업 하네스 | `AGENTS.md`, `CLAUDE.md`, 테스트 명령, 금지 작업, 완료 조건, 문서 규칙 |
| 컨텍스트, 세션, 메모리 관리 | 컨텍스트 윈도우, 세션 분리, resume, compact, 참조 문서, 작업별 맥락 관리 |
| 검증과 평가 | 테스트, 빌드, lint, diff, 리뷰, 재현성, 완료 판단 기준 |
| 권한, 안전, 제어 | sandbox, approval, 위험 명령, 파일 수정 범위, 사람 승인 지점 |
| Agent 루프와 오케스트레이션 | plan, implement, test, review, document 반복 루프, maker-checker, 병렬 세션 |
| 문서화와 지식화 워크플로우 | plan 저장, 작업 로그, 결정 기록, LLM wiki, Obsidian, `docs/refs` 관리 |

## 문서화와 지식화 규칙
- 각 문서는 다른 문서와 연결될 수 있도록 관련 문서 섹션을 둔다.
- 특정 도구에서만 가능한 기능은 `docs/guides` 본문에 길게 설명하지 않고, 원리와 사용 판단 기준만 설명한다.
- 가이드 문서 안에서 외부 자료를 다룰 때는 핵심 관점과 방법론에 필요한 범위로 요약한다.

## README 동기화 규칙
- `docs/guides` 아래의 상위 분류, 문서 목록, 읽는 순서, 관련 문서 위치가 변경되면 `docs/guides/README.md`도 함께 확인한다.
- 사용자가 요청하거나 문서 구조가 바뀐 경우, `docs/guides/README.md`의 목차와 설명을 수정 또는 업데이트한다.
- 새 가이드 분류 폴더나 주요 문서를 추가할 때는 `docs/guides/README.md`에 링크 또는 설명을 추가할지 검토한다.
- `docs/guides/README.md`는 사용자용 안내 문서이고, `docs/guides/AGENTS.md`는 AI Agent용 작성 지침이라는 역할 구분을 유지한다.

## 품질 확인
- 문서 저장 후 UTF-8 인코딩과 한글 깨짐 여부를 확인한다.
- 문서 안의 상대 경로와 링크가 실제 저장 구조와 맞는지 확인한다.
- 도구별 사용법과 상위 작업 방식이 섞이지 않았는지 확인한다.
- 독자가 문서를 읽은 뒤 바로 실행할 수 있는 다음 행동이 있는지 확인한다.
