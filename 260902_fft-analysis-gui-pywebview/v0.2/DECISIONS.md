> 버전: v0.2 · 작성일: 2026-09-02

# DECISIONS

## D-1. 설정은 실행 파일 옆의 단일 JSON 파일로 관리한다

- 선택: 설정 파일은 JSON 형식의 `setting.json` 하나로 만들고 배포된 GUI 실행 파일과 같은 폴더에서 읽고 쓴다. 파일이 없으면 프로그램 기본값과 `Default` 제품을 포함한 파일을 그 위치에 생성한다.
- 근거: 실행 파일과 설정 파일을 함께 복사해 배포·백업할 수 있고 설정의 위치와 내용을 바로 확인할 수 있다. JSON은 Python과 JavaScript 양쪽에서 다루기 쉽고 제품·ROI의 중첩 구조를 표현하기에 적합하다.
- 배제한 대안: YAML은 별도 parser 의존성과 문법 선택지를 늘리고 TXT는 중첩 구조와 자료형을 안정적으로 표현하기 어려워 배제한다. 제품별 파일은 파일 수와 선택 규칙을 늘리고, 운영체제 사용자 설정 폴더는 사용자가 요청한 실행 파일 중심의 이동성과 가시성에 맞지 않아 배제한다.

## D-2. 전역 GUI 설정과 제품별 분석 설정을 계층적으로 분리한다

- 선택: 최상위에서 전역 GUI 설정, 마지막 active product와 여러 제품의 분석 설정을 구분한다. 각 제품에는 물리 크기, TOP-K, FFT 표시 범위와 ROI 목록을 두고 각 ROI에는 이름·정규화 좌표·AVG BAND·REF BAND 등 ROI별 분석값을 둔다.
- 근거: 테마처럼 제품과 무관한 상태의 중복을 막고, 제품 공통값과 ROI별 값을 실제 적용 범위에 맞춰 관리할 수 있다.
- 배제한 대안: 모든 값을 하나의 평면 구조에 저장하면 적용 범위와 소유 관계가 모호해져 배제한다. GUI 설정을 제품마다 중복하거나 ROI별 값을 제품 공통값으로 저장하는 방식은 전환과 복원 시 충돌할 수 있어 배제한다.

## D-3. 설정 편집은 Setting 탭으로 통합하고 명시적으로 저장한다

- 선택: 기존 Overview를 Setting 탭으로 바꾸고 active product 선택, 제품 설정과 ROI 확인·수정·저장을 한곳에서 수행한다. 시작 시 `Default` 또는 마지막 active product를 적용하며 변경 내용은 명시적인 저장 동작으로 반영한다.
- 근거: Overview와 톱니바퀴 Settings modal에 나뉜 흐름을 통합하면 현재 어느 제품을 수정하는지와 저장 시점이 명확해진다.
- 배제한 대안: Overview와 Settings modal을 병행하면 같은 설정의 관리 위치가 분산되어 배제한다. 필드 변경 즉시 자동 저장하는 방식은 실수나 중간 편집 상태까지 반영할 수 있어 배제한다.

## D-4. pywebview는 유지하고 native window chrome은 사용자 정의 chrome으로 교체한다

- 선택: pywebview를 유지하되 frameless 창으로 구성한다. 탭 영역의 빈 공간을 drag region으로 사용하고 창 제어 버튼을 탭 영역 오른쪽에 둔다. 별도 상단 제목 행은 만들지 않고 프로그램 식별 정보는 하단 상태바로 이동한다.
- 근거: Python 수치 분석 runtime과 기존 HTML·CSS UI를 유지하면서 창 외곽까지 디자인 시스템에 통합하고 분석 화면의 세로 공간을 확보할 수 있다.
- 배제한 대안: native 제목 표시줄은 테마와 시각 체계가 분리되어 배제한다. 제목 전용 상단 행은 탭 영역과 기능이 중복되어 배제한다. Electron 교체는 이 변경을 위해 별도 runtime과 배포 체계를 추가하므로 배제한다.

## D-5. 상태바는 파일 문맥과 배포본 식별 정보를 분리해 표시한다

- 선택: 하단 상태바 왼쪽에는 선택한 `.mim` 파일의 Windows 절대 경로를, 오른쪽에는 `FFT ROI Analyzer v0.2 (YY-MM-DD)` 형식의 배포본 정보를 표시한다. 긴 경로는 생략하되 tooltip으로 전체 경로를 제공한다.
- 근거: 분석 대상과 실행 버전을 작업 화면을 가리지 않고 지속적으로 확인할 수 있으며 양쪽 배치로 정보의 역할을 명확히 나눌 수 있다.
- 배제한 대안: 프로그램 제목을 상단에 유지하면 compact chrome과 충돌해 배제한다. 파일명만 표시하면 같은 이름의 파일을 구분할 수 없고, 긴 경로를 줄바꿈하면 상태바 높이가 불안정해져 배제한다.

## D-6. 세 가지 테마는 공통 design token으로 관리하고 Gray를 기본값으로 한다

- 선택: Dark·Gray·White 테마를 공통 token으로 정의해 GUI, 그래프, 테이블과 아이콘에 함께 적용한다. 기본은 Gray로 하고 White → Gray → Dark → White 순서로 전환하며 마지막 선택을 전역 GUI 설정으로 저장한다.
- 근거: 작업 환경에 맞는 명도를 선택하면서 구성 요소별 색상 불일치를 막을 수 있다. Gray는 장시간 분석 시 순백색보다 눈부심이 적고 Dark보다 일반 업무 환경과의 명도 차이가 작다.
- 배제한 대안: Dark 단일 테마는 선택권이 없어 배제한다. 구성 요소별 직접 색상 지정은 테마 전환 누락을 만들고, 시스템 테마만 자동 추종하는 방식은 앱 안의 명시적 선택과 복원을 충족하지 못해 배제한다.

## D-7. 그래프는 Plotly를 유지하되 Matplotlib형 직사각형 frame으로 재설계한다

- 선택: Plotly.js를 유지하고 네 변이 보이는 직사각형 frame, 하단 X축, 좌측 Y축과 절제된 grid를 적용한다. Profile과 FFT는 GUI 글꼴과 theme token을 사용하고 plot 영역의 좌측 시작 위치를 맞춘다.
- 근거: Plotly의 zoom·pan·tooltip을 유지하면서 기본 흰색 배경과 내부 십자축을 제거해 전문 scientific 분석 도구의 시각 체계에 맞출 수 있다.
- 배제한 대안: Plotly 기본 template은 GUI 테마와 분리되어 배제한다. 내부 십자축은 데이터 위에 불필요한 강조를 만들고, Matplotlib 정적 이미지로 교체하면 웹 기반 상호작용이 약화되므로 배제한다.

## D-8. 물리 단위 변환은 ROI의 실제 sampling 조건을 기준으로 한다

- 선택: 분석 방향의 Physical Width 또는 Height가 0보다 크면 Profile과 period는 mm, FFT는 cycles/mm로 표시한다. 해당 ROI의 물리 span과 profile sample 수로 sampling 간격을 구하며, 분석은 sample 좌표에서 수행한 뒤 표시 좌표만 변환한다.
- 근거: 같은 제품에서도 ROI 크기와 sample 수에 따라 sampling 간격과 Nyquist 주파수가 달라지므로 실제 ROI 조건을 기준으로 해야 px와 mm가 같은 현상을 나타낸다.
- 배제한 대안: 제품 전체 물리 크기를 모든 ROI에 직접 적용하면 ROI 비율을 무시해 배제한다. mm 좌표로 먼저 변환해 분석하면 수치 정밀도가 저하될 수 있고, 물리 크기 0에 임의 환산값을 쓰면 근거 없는 단위를 만들므로 배제한다.

## D-9. FFT 기본 표시 범위는 Nyquist 대비 비율로 정한다

- 선택: 기본 X축 상한은 제품 설정 `fft_display_range_percent`를 해당 ROI와 방향의 Nyquist 주파수에 적용해 구한다. 기본값은 40%이고 표시 범위만 제한하며 전체 FFT 결과는 유지한다.
- 근거: px와 mm 또는 서로 다른 sampling 간격에서도 같은 상대적 확대 수준으로 spectrum을 볼 수 있다.
- 배제한 대안: `0.2` 같은 고정 숫자는 단위가 바뀌면 의미가 달라져 배제한다. 범위 밖 FFT bin을 제거하면 추가 zoom·pan 분석을 막고, peak마다 자동 범위를 바꾸면 ROI 간 비교 기준이 불안정해져 배제한다.

## D-10. Horizontal과 Vertical은 독립 분석으로 유지하고 All에서 병렬 비교한다

- 선택: Direction은 Horizontal·Vertical·All로 구성한다. All에서는 Horizontal을 왼쪽, Vertical을 오른쪽에 배치하고 각 방향에 독립된 Profile·FFT와 peak 선택 상태를 둔다. TOP PEAKS 테이블도 방향별로 분리한다.
- 근거: 두 방향의 sampling 길이, 단위와 FFT peak가 다를 수 있으므로 계산과 상태를 분리해야 한다. All은 결과의 소유 관계를 유지하면서 동시 비교를 제공한다.
- 배제한 대안: 두 방향 trace를 같은 축에 겹치면 단위·범위·peak 표식이 충돌할 수 있어 배제한다. 단순 방향 전환은 동시 비교를 제공하지 못하고, 두 방향의 선택 상태 공유는 다른 주파수를 같은 선택으로 오인하게 해 배제한다.

## D-11. TOP-K peak는 순번과 고유 색상을 공유하는 하나의 상호작용 객체로 다룬다

- 선택: TOP PEAKS 행, FFT marker와 badge, Profile 주기선을 peak 순번으로 연결하고 같은 고유 색상을 사용한다. 테이블과 FFT 양쪽에서 다중 선택·해제할 수 있으며 색상 외에 `[순번] X축값`을 항상 표시한다.
- 근거: 같은 peak가 표, 주파수 그래프와 공간 Profile에서 어떻게 대응하는지 추적할 수 있고 순번을 병기하면 색각 차이나 테마 변화에도 식별성을 유지한다.
- 배제한 대안: 동일한 노란색 `x`는 항목 간 대응을 구분할 수 없어 배제한다. 한쪽 UI에서만 선택하는 방식은 분석 흐름을 제한하고, 단일 선택은 여러 주기의 공간 패턴 비교를 막으므로 배제한다.

## D-12. Profile 주기선은 전역 위상 오프셋으로 정합한다

- 선택: FFT peak의 주파수를 인접 bin 보간으로 정밀 보정하고, 보정된 주기 간격은 고정한 채 Profile의 반복 peak 또는 valley와 전체 오차가 최소가 되는 단일 위상 오프셋을 구한다. 두 극성의 정합 점수를 비교하고 보정 주파수·주기·오프셋·극성·정합 점수를 관리한다. 방향과 선택 peak별로 독립 계산한다.
- 근거: 기존 `0, T, 2T, ...` 방식은 주기 간격만 반영하고 실제 Profile 위상을 반영하지 않는다. 전역 정합은 위치 오차를 줄이면서 FFT로 얻은 동일 간격을 보존하고 밝고 어두운 반복 패턴을 모두 다룰 수 있다.
- 배제한 대안: 0에서 시작하는 고정 위상은 실제 peak 위치와 무관해 배제한다. 각 선을 개별 peak로 이동하면 주기 간격이 변형되어 배제한다. FFT 복소 위상만 쓰는 방식은 비정수 bin, spectral leakage, 잡음과 비정현파에 민감해 단독 사용하지 않는다.

## D-13. Setting 이미지의 zoom·pan은 일반 분석·그래픽 도구의 조작 규칙을 따른다

- 선택: Wheel은 pointer 중심 zoom, Space+왼쪽 drag와 가운데 버튼 drag는 pan으로 사용한다. `Ctrl+0`은 Fit, `Ctrl+1`은 100%, `+`와 `-`는 단계 zoom으로 사용한다. 이미지, grid와 ROI는 같은 변환을 공유하되 ROI label과 handle은 화면상 고정 크기를 유지한다.
- 근거: 익숙한 조작으로 학습 부담을 줄이고 zoom 상태에서도 ROI와 원본 이미지의 좌표 일치를 유지한다. ROI 편집과 pan에 다른 입력을 배정해 기존 왼쪽 drag 편집을 보존한다.
- 배제한 대안: modifier 없는 왼쪽 drag pan은 ROI 편집과 충돌해 배제한다. 이미지와 ROI의 별도 변환은 좌표를 어긋나게 하고, zoom에 따라 handle까지 확대하면 배율별 편집성이 달라져 배제한다.

## D-14. 이미지 grid는 분석 데이터가 아닌 표시 overlay로 관리한다

- 선택: grid는 기본적으로 숨기고 toggle로 표시한다. 이미지와 같은 zoom·pan 변환을 적용하되 ROI보다 뒤에 그리고 이미지 경계에서 clip한다. grid는 원본 이미지, ROI 좌표와 분석 결과를 바꾸지 않는다.
- 근거: 위치와 scale 확인용 보조 정보이므로 분석값과 분리해야 하며 이미지와 함께 변환해야 소속 좌표가 명확하다.
- 배제한 대안: image pixel에 합성하면 원본 표시와 분석 입력을 혼동할 수 있어 배제한다. ROI 앞에 표시하면 경계와 handle을 가리고, 기본 표시는 이미지 관찰을 방해할 수 있어 배제한다.

## D-15. Explorer는 MIM 데이터만 노출하는 계층형 tree로 구성한다

- 선택: GitHub 방식의 펼침·접힘 tree를 사용하고 `.mim` 파일과 이를 직접 또는 재귀적으로 포함하는 폴더만 표시한다. 폴더 클릭은 경로 이동 대신 펼침·접힘으로 동작하며 폴더와 파일은 icon과 글꼴 굵기로 구분한다.
- 근거: 처리할 수 없는 파일과 빈 경로를 제거해 대상 데이터를 빠르게 찾고, 계층을 유지한 채 여러 폴더를 비교할 수 있다.
- 배제한 대안: 폴더 클릭 경로 이동은 상위 문맥과 다른 펼침 상태를 잃게 해 배제한다. 모든 파일과 `.mim` 없는 폴더 표시는 분석 대상으로 이어지지 않는 항목으로 목록을 복잡하게 해 배제한다.

## D-16. 프로그램과 Explorer 아이콘은 하나의 scientific line-icon 체계로 제작한다

- 선택: 대표 아이콘은 FFT와 ROI 분석의 성격을 작은 크기에서도 식별할 수 있는 단순한 scientific 형태로 만들고 실행 파일·창·작업 표시줄에 동일하게 적용한다. Explorer icon도 같은 시각 언어로 구성하고 세 테마의 token에 맞춘다.
- 근거: 앱 외부와 내부의 브랜드를 연결하고 SSOT인 전문 scientific 분석 도구의 인상을 작은 UI 요소까지 유지할 수 있다.
- 배제한 대안: PyInstaller나 운영체제 기본 icon은 앱 목적을 전달하지 못해 배제한다. 세부 묘사와 장식이 많은 icon은 작은 크기에서 형태가 무너지고, 고정 색상 icon은 일부 테마에서 대비가 부족해 배제한다.
