# 검증 범위와 판정 항목

## 확정된 요구

[BRIEF](../BRIEF.md)의 검토용 완료 조건을 검증할 방법을 정리한다. 이 문서는 테스트
계획 후보이며 실행 결과가 아니다. 첫 버전 Task, 환경과 수치 허용 오차는 미정이다.

## 검토 제안: 검증 행렬

### 검증 순서와 Ignite 착수 조건

1. v0.1에서 Lightning Wrapper·Trainer·DataModule·LightningCLI와 학습·평가·예측을 구현한다.
2. v0.1 범위로 정한 공통 변환·후처리·가중치 복원·독립 Predictor를 함께 검증한다.
3. 확정한 Lightning 검증·테스트를 완료하고 실제 호출·설정·반환 계약과 결과를 기록한다.
4. 위 작업이 끝난 다음 사용자가 지정한 v0.2 또는 그 이후 버전에서 Ignite 구현을 시작한다.
5. 후속 버전에서 검증된 Lightning API를 기준으로 Ignite의 동작과 호환성을 검증한다.

아래 행렬의 Ignite 열과 양쪽 비교 항목은 후속 검증이다. v0.1에는 Lightning과 공통 코드·
독립 Predictor에 해당하는 항목을 적용하며, Ignite 미구현 때문에 v0.1 검증을 실패로
판정하지 않는다. 각 행의 양쪽 최종 설정·공개 API 비교도 Ignite 구현 버전에서 수행한다.

v0.1 검증·테스트 완료 전 Ignite 구현을 진행하지 않는다. 현재는 문서 작성 단계이며
위 완료 조건을 달성했다거나 Ignite 착수 조건을 충족했다는 의미는 아니다.

구현 대상으로 정한 각 Task에 아래 행렬을 적용한다. 전체 지원 방향이 여덟 Task라는
이유로 첫 버전의 구현·검증 범위를 자동으로 여덟 Task로 정하지 않는다.

| 검증 대상 | Lightning | Ignite | 독립 Predictor |
| --- | --- | --- | --- |
| 학습 중 파라미터 업데이트 | native 학습 | Engine 학습 | 해당 없음 |
| 정답 기반 평가 | native 검증·평가 | evaluator | 현재 필수 범위 아님 |
| 정답 없는 예측 | native 예측 | 예측 Engine | 독립 추론 |
| Dataset 입력 | DataModule 연결 | 프로젝트 DataModule 연결 | 필요 시 변환된 입력 재사용 |
| 기존 Loader 입력 | 기존 설정 보존 | 기존 설정 보존 | 준비된 배치 경로 |
| 추론용 저장·복원 | 내보내기 원천 | 내보내기 원천 | 복원 대상 |
| 같은 후처리 | native step에서 호출 | Engine 경로에서 호출 | Predictor에서 호출 |
| 같은 공개 API | fit·validate·test·predict | 프로젝트 Trainer의 같은 호출 | 별도 추론 API |

## 검증 시나리오 후보

| 항목 | 방법 | 확인할 결과 |
| --- | --- | --- |
| 모델 재사용 | 기존 모델을 수정 없이 Wrapper에 전달 | 학습·평가·예측 실행, 원본 모델 코드 변경 불필요 |
| 학습 유효성 | 고정 소형 입력으로 학습 전후 파라미터 확인 | 의도한 구성요소에 업데이트 발생, Loss가 유한함 |
| transform 중복 | 호출 횟수 기록과 수치가 알려진 입력 사용 | Dataset에서 한 번, 준비된 배치 Predictor에서 추가 적용 없음 |
| 사용자 정의 전처리 | transform 또는 선택적 Preprocessor를 지정·미지정하여 실행 | 지정 시 의도한 위치에서 수행, 미지정 시 기본 경로 유지 |
| 전처리 대체·추가 | 입력 상태와 호출 횟수를 단계별 확인 | 대체 시 기존 변환 중복 없음, 추가 시 지정한 처리만 수행 |
| 원시 입력 추론 | 같은 원시 샘플에 평가용 transform 적용 | Dataset 경로와 같은 모델 입력 구성 |
| 후처리 공유 | 알려진 logits·연속값·복원값 사용 | 예상 예측값과 일치, 원시 출력 불변 |
| Loss·Metric 분리 | logits Loss와 점수 기반 지표 사용 | 최종 argmax 결과로 원시 정보가 대체되지 않음 |
| 가중치 복원 | 같은 상태를 내보내고 새 모델로 복원 | 가중치 키·shape 대응과 저장 전후 결과 일치 |
| native 예측 유지 | native API/Engine 경로 실행 확인 | 독립 Predictor에 위임하지 않고 native 경로 동작 |
| 공통 Trainer 호출 | 같은 호출 형태로 양쪽 백엔드 실행 | fit·validate·test·predict가 해당 native 경로에 연결 |
| 검증·평가 분리 | 서로 다른 validation/test 데이터로 연속 실행 | 올바른 Loader 사용, Metric 상태 누적·혼합 없음 |
| 주요 Hook 계약 | Task Hook 호출과 결과 전달 확인 | 공통 인자·반환 규칙 및 최적화 책임 준수 |
| 공개 반환 계약 | 같은 Task·설정의 공개 결과 구조 검사 | 평가·예측의 확정 스키마 준수, 내부 State 직접 해석 불필요 |
| LightningCLI 직접 사용 | CLI 진입점과 명령 연결 확인 | 실제 LightningCLI가 객체 생성·native 실행을 담당, 명령 중복 실행 없음 |
| Lightning native 전반 유지 | Wrapper·Trainer·데이터·학습·검증·평가·예측 경로 확인 | native 클래스와 Hook 사용, Ignite 호환을 위한 대체 루프나 기능 제한 없음 |
| Ignite의 API 대응 | 같은 주요 Wrapper Hook과 Trainer API로 실행 | 내부 Engine에서 Hook 호출과 학습·평가·예측 수행 |
| config와 CLI 덮어쓰기 | 파일 기본값과 뒤따르는 --xxx 값 입력 | 같은 공통 옵션에 대해 양쪽 CLI의 최종 설정 일치 |
| 설정 출력 | --help·--print_config 호출 | 인자·최종 설정 확인 가능, 학습·평가·예측 미실행 |
| 적용 설정 기록 | 덮어쓴 설정으로 실행 후 기록 확인 | 최종 적용값 보존, 재사용 시 설정 재현 |
| 미지원 CLI 옵션 | 지원표에 없는 키·클래스 입력 | 조용히 무시하지 않고 명확히 보고 |
| 독립 의존성 | Lightning·Ignite 미설치 환경에서 import·추론 | 백엔드 없이 모델·변환·복원·후처리 사용 가능 |
| 반복 호출 | 평가·예측을 연속 실행 | Metric·결과 누적과 handler 중복 없음 |
| 입력 누락·설정 충돌 | 필수 단계 누락, Dataset·Loader 중복 등 | 확정된 정책에 따른 오류 또는 명시된 처리 |

## 예측 경로 비교

한 백엔드에서 얻은 같은 학습 가중치를 내보내 native 예측과 독립 Predictor를 비교한다.
다른 백엔드에서 별도로 학습한 모델의 가중치나 결과가 같아야 한다는 조건은 두지 않는다.

1. 같은 샘플 ID, 모델 가중치, 평가 모드, dtype·장치를 기준으로 정렬한다.
2. transform·후처리·임계값·원본 크기 정보를 동일하게 제공한다.
3. 모델 입력, 원시 출력, 후처리 결과를 단계별로 비교하여 차이를 찾는다.
4. native 결과 목록과 샘플별 결과를 맞춘 뒤 비교한다. 배치 묶음 차이를 오류로 오인하지 않는다.

결정론적 결과에는 수치 허용 오차를 정하고, 클래스·마스크·박스 등 의미별 판정 기준을
별도로 둔다. VAE/GAN은 잠재 입력과 난수 정책을 맞추거나 확률적 출력의 검증 방법을
따로 정해야 한다. 고정된 출력 해시나 모든 장치의 완전 일치를 기본 조건으로 삼지 않는다.

## Task별 추가 확인 후보

회귀는 타깃 역변환의 단위, Detection은 가변 개수·빈 탐지와 좌표 복원, Segmentation은
마스크 크기와 클래스, Anomaly는 연속 점수와 임계값 판정, AE/VAE는 복원 대상과 출력
공간, GAN은 구성요소별 업데이트와 잠재 입력을 확인한다.

## 검증 기록

구현 시 데이터·모델 식별자, 가중치 선택, 라이브러리 버전, 환경, 실행 명령, 판정 기준과
결과를 남기는 방안을 제안한다. 실제 결과는 구현이 시작된 뒤 PROGRESS에 기록한다.
현재 실행한 학습·추론 테스트는 없으며 성공률이나 처리 성능을 주장하지 않는다.

## 미정

검증 대상, CPU/GPU 범위, 수치 오차, 데이터 크기, 성능 목표와 선택 기능의 검사 항목은
사용자가 버전 범위와 환경을 정한 뒤 확정한다.
